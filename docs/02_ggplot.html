Data Visualisation with ggplot2

We’re going to create some plots using functions from the ggplot2 package. R packages usually contain functions related to a specific activity, which in this case is data visualisation, and also documentation which outlines how the functions work.

We’ve already installed the ggplot2 package. It was installed as part of the tidyverse package, which is a popular collection of packages developed by the same group of people.

The na.omit() function will remove all rows for which an NA exists anywhere in the row (i.e., hindfoot_length, weight or sex in this case). This gives us a nice clean dataset for today, but you may want to use it cautiously on your own data.

Plotting with ggplot2

The ‘gg’ in ggplot2 stands for “grammar of graphics”, which refers to a particular way of creating plots using a consistent vocabulary and layering different elements on. Therefore, we only need small changes to our code if the underlying data changes or we decide to make a box plot instead of a scatter plot. This approach helps you create publication-quality plots with minimal adjusting and tweaking.

ggplot plots are built step by step by adding new layers, which allows us to customise and test as we go. The basic format for the ggplots template is as follows:

  • Specify the data as a dataframe in long format

  • Map variables (i.e., map which column to the x or y axis)

  • Choose the geometry function to create the plot type

We’re going to use the following template to build our plots:

ggplot(data = <DATA>, mapping = aes(<MAPPINGS>)) + <GEOM_FUNCTION>()

We need to change everything inside <>.

First we need to specify the data we want to use. Next, we can see that the ggplot() call has a function nested within it, aes(), which relates to aesthetic mappings. This is where we specify which parts of the data should be mapped to different axes on our plot. Finally, we need to specify the geometry we want to use, or in other words, the plot type. The geometry function we use is added to the end with a + sign.

Let’s go through step by step. First we need to specify the dataset.

ggplot(data = survData)

We get a blank plot because we haven’t told ggplot() which variables we want to correspond to parts of the plot.

Let’s map variables to axes:

ggplot(data = survData, mapping = aes(x = weight, y = hindfoot_length))

Now we’ve got a plot with x and y axes corresponding to variables from surveys. However, we haven’t specified how we want the data to be displayed. We do this using geom_ functions, which specify the type of geometry we want, such as points, lines, or bars. Because geom_point() is a new layer, we add it to our plot using the + sign.

ggplot(data = survData, mapping = aes(x = weight, y = hindfoot_length)) + geom_point()

It is good practice to use indentation to format our code, and this becomes essential as our code gets longer. Each time you reach a new argument (separated by a comma) hit enter or return, and R will automatically format the code on a new line. Put each layer on a new line, ending the previous line with the + sign. Try re-writing the code above as below, then run it to generate the plot.

# Two numeric variables - scatter plot
ggplot(data = survData, 
       mapping = aes(x = weight, y = hindfoot_length)) +
  geom_point()
TipWhat is # doing here?

Comment (#): Text in your script preceded by a hashtag. R ignores this text, allowing you to write a brief note about why you did something the way you did.

NoteWhat if our dataset contains NAs

Let’s try to plot our original object surveys, which contains NAs in the dataset:

ggplot(data = surveys, 
       mapping = aes(x = weight, y = hindfoot_length)) +
  geom_point()
Warning: Removed 3081 rows containing missing values or values outside the scale range
(`geom_point()`).

You may notice a warning that missing values were removed, although we got the same plot.

This is because if a variable necessary to make the plot is missing from a given row of data (in this case, hindfoot_length or weight), that observation can’t be plotted. ggplot2 warns us that this has happened to ensure we know there are missing values.

Another common type of message is an error, which means R can’t execute the command. This is commonly due to misspelling, or missing punctuation such as brackets or commas.

Try different geom functions

This is where the grammar of graphics pays off. To make a completely different kind of plot, we keep the same template and change only the geom (and sometimes which columns we map). ggplot2 has more than 40 geoms; today we’ll try three that you will use most often.

Our scatter plot used geom_point() to show the relationship between two numeric variables. Let’s see what happens when we change the geom, and nothing else.

One numeric variable — a histogram shows the distribution of a single column, so we only map x:

# One numeric variable - histogram
ggplot(data = survData,
       mapping = aes(x = weight)) +
  geom_histogram()
`stat_bin()` using `bins = 30`. Pick better value `binwidth`.

Notice the message: ggplot2 chose 30 bins for us and suggests we pick a better value. We can do that with the bins argument (or binwidth).Let’s use bins = 50 to divide the data into 50 bars:

# One numeric variable - histogram
ggplot(data = survData,
       mapping = aes(x = weight)) +
  geom_histogram(bins = 50)

Counts of a categorical variable — a bar chart counts how many rows fall into each category. We only map x, and geom_bar() does the counting:

# Counts of a categorical variable - bar chart
ggplot(data = survData,
       mapping = aes(x = plot_type)) +
  geom_bar()
Tipgeom_bar() vs geom_col()

geom_bar() counts rows for you, so it only needs x. If your data already contains the number you want to plot (for example a column of means you calculated), use geom_col() and map that column to y.

A numeric variable across categories — a boxplot summarises the distribution of a numeric variable within each group of a categorical variable. We map the category to x and the number to y:

# A numeric variable across categories - boxplot
ggplot(data = survData,
       mapping = aes(x = plot_type, y = hindfoot_length)) +
  geom_boxplot()

You may have noticed that the long labels on the x axis overlap. A quick fix is to put the categorical variable on the y axis instead.

# A numeric variable across categories - boxplot, categories on the y axis
ggplot(data = survData,
       mapping = aes(y = plot_type, x = hindfoot_length)) +
  geom_boxplot()

Which plot should I use? From Data to Viz

Knowing how to make a plot is only half the job. The other half is deciding which plot answers your research question. Two things determine that:

  1. Your question: are you looking at the distribution of one variable, a comparison between groups, a relationship between two variables, a change over time, or parts of a whole?
  2. Your data types: how many variables are involved, and is each one numeric or categorical?

Once you know those two things, the choice of geom usually follows.

From Data to Viz is an excellent tool. It is a decision tree: you start from what your data looks like (numeric, categorical, a mix, time series, maps, networks), follow the branches, and it leads you to the plot types that suit it. Let’s take a look at it together.

Three things to notice on the site:

  • Each plot type has a short description of when to use it and its common mistakes.
  • Every plot type also has an R graph gallery link with ready-made ggplot2 code. This is how most people actually find the code for a plot they haven’t made before.
  • The code you find will use their dataset and column names. To reuse it, map it back onto our template: replace the data, replace the column names inside aes(), and keep the geom and any extra layers.

We find this website a useful tool for learning ggplot2 and designing publication figures. It not only gives you the R code, but also adds a layer of decision-making: which figure best fits your data and your research question.

Building a better plot step by step

So far we’ve made quick plots to look at our data. Now let’s take one plot all the way to something you could put in a paper or a thesis.

Let’s go back to our survey dataset, survData. We’d like to draw a figure to answer our research questions:

How do body weights compare between the different rodent genera in our surveys? And does the plot type make any difference?

That’s one numeric variable (weight) across the categories of one categorical variable (genus), so a boxplot is a good starting point. We’ll improve it in small steps, running the code each time so we can see what each change does.

Step 1: The basic boxplot

ggplot(data = survData,
       mapping = aes(x = genus, y = weight)) +
  geom_boxplot()

It works, but it isn’t very readable. The genus names overlap, and most of the boxes are squashed at the bottom of the plot because a few animals are very heavy.

Step 2: A log scale for skewed data

When data is skewed like this (i.e., most values are small, with a long tail of very large ones), a log scale spreads out the small values and pulls in the large ones, so every group gets some space. We add a scale layer, scale_y_log10(), which keeps the real values (grams) on the axis labels.

ggplot(data = survData,
       mapping = aes(x = genus, y = weight)) +
  geom_boxplot() +
  scale_y_log10()

Now we can actually see all nine boxes.

Step 3: Turn it sideways for easy reading

The genus names are long and overlap on the x axis. Category labels are much easier to read on the y axis. We saw this trick earlier: swap the x and y mappings. Because weight is now on the x axis, the scale layer also becomes scale_x_log10().

ggplot(data = survData,
       mapping = aes(y = genus, x = weight)) +
  geom_boxplot() +
  scale_x_log10()

Step 4: Put the groups in a sensible order

At the moment the genera are in alphabetical order, which is not very meaningful. Ordering groups by their median makes the comparison much easier to read.

To do this, we tell R the order of the categories using the fct_reorder() function from the forcats package (part of the tidyverse). It converts genus into a special type of categorical variable called a factor, ordered by the median weight. We’ll learn more about factors tomorrow.

For now, we replace the genus column in survData with the reordered version:

survData$genus <- fct_reorder(survData$genus, survData$weight, .fun = median)
TipWhat does <- do here?

<- stores the result on the right into the name on the left. Here the name is an existing column, survData$genus, so that column is overwritten with the reordered version. The original CSV file is not changed.

Keyboard shortcut for <-: Alt + - on Windows, Option + - on Mac.

Then run the same plotting code as before:

ggplot(data = survData,
       mapping = aes(y = genus, x = weight)) +
  geom_boxplot() +
  scale_x_log10()

The genera now run from lightest (bottom) to heaviest (top), and the plot tells a story at a glance.

Step 5: Add labels

Now that the structure is right, let’s make it look good, starting with the words. labs() sets the title and axis labels in one go. Good labels say what is plotted and the units.

ggplot(data = survData,
       mapping = aes(y = genus, x = weight)) +
  geom_boxplot() +
  scale_x_log10() +
  labs(title = "Body weight varies widely between rodent genera",
       x = "Weight (g, log scale)",
       y = "Genus")

Step 6: A theme

A theme controls everything on the plot that isn’t data: the background, the grid lines, the text. ggplot2 comes with several complete themes. Let’s swap the default grey background for theme_minimal():

ggplot(data = survData,
       mapping = aes(y = genus, x = weight)) +
  geom_boxplot() +
  scale_x_log10() +
  labs(title = "Body weight varies widely between rodent genera",
       x = "Weight (g, log scale)",
       y = "Genus") +
  theme_minimal()
TipOther built-in themes

Try theme_bw(), theme_classic(), theme_light() or theme_dark() in place of theme_minimal(). Adding theme(...) after a complete theme, as we do next, lets you override just the parts you want to change.

A complete theme is a good start, but we usually want to adjust a few details. The theme() function lets us change individual parts of the plot. Each argument names a part of the plot (plot.title, axis.title, panel.grid.major.y, and many more) and we give it an element function describing what it should look like: element_text() for text, element_line() for lines, or element_blank() to remove it altogether.

Let’s make the title bold and centred (hjust = 0.5), and see how it looks like. Then, because the y axis is categorical, we don’t need the horizontal grid lines, let’s remove them using panel.grid.major.y:

ggplot(data = survData,
       mapping = aes(y = genus, x = weight)) +
  geom_boxplot() +
  scale_x_log10() +
  labs(title = "Body weight varies widely between rodent genera",
       x = "Weight (g, log scale)",
       y = "Genus") +
  theme_minimal() +
  theme(plot.title = element_text(face = "bold", hjust = 0.5),
        panel.grid.major.y = element_blank())

Our code is getting long, and we’re going to keep adding to it. It’s a good idea to store everything except the geom_boxplot() in an object called plot_weight. That way we can try different geoms on top of the same base without retyping it. Running the object’s name followed by + geom_boxplot() gives us the same plot as before.

# Create object, plot_weight, without geom
plot_weight <- ggplot(data = survData,
                      mapping = aes(y = genus, x = weight)) +
  scale_x_log10() +
  labs(title = "Body weight varies widely between rodent genera",
       x = "Weight (g, log scale)",
       y = "Genus") +
  theme_minimal() +
  theme(plot.title = element_text(face = "bold", hjust = 0.5),
        panel.grid.major.y = element_blank())

# Use + to add geom to draw your plot
plot_weight +
  geom_boxplot()
TipWhat are an object and <-?

Object: A named “container” in R that holds information. Almost everything in R, from a single number to a giant dataset, is an object. We will explain it a little more tomorrow.

Assignment (<-): The “left arrow” operator used to store a value into an object. For example, x <- 10 means “put the number 10 into an object named x.” Alt + - on Windows, Option + - on Mac.

Step 7: Show the data, not just the summary

A boxplot is a summary: it hides how many observations are in each group and what their spread really looks like. Layering the raw data on the plot fixes that. We’ll build this up in four small moves.

Add the points. geom_jitter() is geom_point() with a little random spread, so that points with the same value don’t sit exactly on top of each other. Because plot_weight already holds the data and the mappings, we only need to add the geom:

plot_weight +
  geom_boxplot() +
  geom_jitter()

Look at Baiomys at the bottom: only three animals. The boxplot alone would never have told you that.

Look at this plot: that’s more than 13,000 points, and they’ve completely covered the boxes. We need to make the points smaller and transparent, and keep them within their own row.

Tune the points. Three arguments inside geom_jitter() do this: alpha sets transparency (0 is invisible, 1 is solid), size sets the point size, and height controls how far the points are spread vertically across the genus categories. (If your categories were on the x axis you would use width instead.)

plot_weight +
  geom_boxplot() +
  geom_jitter(alpha = 0.2, size = 1, height = 0.2)

Looks better: we can now see where the data is dense. But the points are still drawn over the boxes, and they overlap with the boxplot’s own outlier points.

Order the layers. Note that layers are drawn in the order you add them, so to put the boxes on top we add geom_jitter() first and geom_boxplot() second. While we’re there, we make the boxes semi-transparent too, and use outlier.shape = NA to hide the boxplot’s own outlier points, since the jittered points already show them.

plot_weight +
  geom_jitter(alpha = 0.2, size = 1, height = 0.2) +
  geom_boxplot(outlier.shape = NA, alpha = 0.5)

Colour the points by genus. So far every argument we’ve given a geom has been a fixed value that applies to every point: alpha = 0.2, size = 1. To make the colour depend on the data we need a mapping, and mappings always go inside aes(). We can put an aes() inside a single geom, and it applies to that layer only, which means the boxes stay black.

plot_weight +
  geom_jitter(mapping = aes(colour = genus), alpha = 0.2, size = 1, height = 0.2) +
  geom_boxplot(outlier.shape = NA, alpha = 0.5)
TipInside or outside aes()?

This is the most common ggplot2 mix-up. Inside aes(), you name a column and ggplot2 maps its values to colours, adding a legend: aes(colour = genus). Outside aes(), you give a fixed value that applies to the whole layer: colour = "blue".

If you write aes(colour = "blue"), ggplot2 treats "blue" as a one-category variable and you get salmon-pink points with a legend saying “blue”. Try it!

Step 8: Split the plot by plot type

Our surveys come from five different plot types: the control plots, and four kinds of experimental exclosure that keep out particular animals.

Are the weights the same in each? Rather than squeezing everything into one panel, we can make a small copy of the plot for each plot type using facet_wrap(). Inside it we name the column to split by within vars().

plot_weight +
  geom_jitter(mapping = aes(colour = genus), alpha = 0.2, size = 1, height = 0.2) +
  geom_boxplot(outlier.shape = NA, alpha = 0.5) +
  facet_wrap(vars(plot_type))

Every panel shares the same axes, so the panels can be compared directly. The weights within each genus are similar across plot types, but look at how many points there are: Dipodomys (the kangaroo rats, or “Krats”) dominate the Control panel, and are almost absent from the Long-term Krat Exclosure. This is exactly what that exclosure was designed to do.

This is the structure of our finished plot, so let’s save it to an object:

plot_weight_final <- plot_weight +
  geom_jitter(mapping = aes(colour = genus), alpha = 0.2, size = 1, height = 0.2) +
  geom_boxplot(outlier.shape = NA, alpha = 0.5) +
  facet_wrap(vars(plot_type))

If you want, you can control the layout of the panels with ncol or nrow, for example facet_wrap(vars(plot_type), nrow = 1) to put all five side by side. Try it yourself!

  2. Remove the legend — the genus names are already on the y axis. (Hint: the legend is controlled by theme(legend.position = ...).)
  3. Assign the result back to plot_weight_final, so that the version we export in the next section is the coloured one.
TipSolution

The final code looks like below. Scales and theme settings are layers too, so they are added with + just like a geom. Assigning back to the same name replaces the old object with the updated plot.

plot_weight_final <- plot_weight_final +
  scale_colour_viridis_d() +
  theme(legend.position = "none")

Exporting plots

Once we’re happy with our plot, we can save it using the ggsave() function.

We need to specify the following arguments:

  • filename: the filename we’re using to save our plot, including the file type of the image (e.g. “.jpg”, “.png”, “.tif”).
  • plot: the name of the plot object we want to save.
  • widthand height: the size of the saved image (in inches by default).
ggsave("figures/weight-by-genus.png", plot = plot_weight_final, width = 8, height = 5)

You can also specify one of the below optional arguments to set where the image will be saved:

  • path: the path of the directory we want to save our plot in (if not already in our filename).
  • create.dir: whether to create a new directory if the directory specified in path doesn’t exist.

File type

ggplot supports both vector and raster formats. Vector formats store images as instructions, which means they can be resized without any loss of quality, whereas raster formats store images as fixed arrays of pixels, meaning they cannot be resized without losing quality. The JPEG format we used above is an example of a raster format - the image resolution is fixed when it is saved, so it cannot be resized very much without looking bad.

Supported vector formats:

  • .pdf (Portable Document Format, when unflattened)
  • .svg (Scalable Vector Graphics)
  • .eps (Encapsulated PostScript)

Supported raster formats:

  • .png (Portable Network Graphics)
  • .jpg or .jpeg (Joint Photographic Experts Group)
  • .tiff or .tif (Tagged Image File Format)
  • .bmp (Bitmap)

Sometimes a journal will ask for figures in a vector format so that they can size the image appropriately based on the typesetting of the document. Otherwise, most of the time you’ll select a raster format and set the size of the image yourself. To do this you need to use the following optional arguments:

  • width & height: plot size in units defined by the units argument.
  • units: one of the following - “in”, “cm”, “mm”, “px” (defaults to inches).
  • dpi: plot resolution in dots per inch (defaults to 300).

Clarifying DPI

Confusion around DPI is common. People often conflate DPI with other attributes of images relating to their size, or to the supposed ‘quality’ of an image.

There are three properties that determine the size and quality of an image:

  • Resolution: the pixel dimension of a screen or an object on a screen, expressed as width x height (e.g. 1920x1080).
  • Print size: the physical dimensions of an image when printed, typically measured in inches for photos.
  • DPI: Dots per inch, or the density of ink dots printed onto paper.

To obtain the print size of an image, the resolution is divided by the DPI set inside the image metadata. For example, if an image has a resolution of 900x900 pixels, and the DPI in the image is set to 300, then the image will be printed at 3 x 3 inches. The DPI setting inside the metadata of a digital image has absolutely no bearing on how that image is represented on a screen, only when it is printed or added into something like a Word doc which shows you how a document will look when printed.

It’s common for journals to ask for figures based only on a particular DPI (often 300), but this by itself is meaningless. You could send them an image with a resolution of 150 x 150 pixels and a DPI set to 300, but when printed it would only be half an inch by half an inch. What they really mean is they want images with “a resolution large enough to display the image at the chosen size when printed.”

If you need to set a DPI and physical size, then the resolution will be determined by multiplying the two together. For example, let’s say we need our plot to be 8 x 5 inches on the page and 600 DPI.

ggsave("figures/weight-by-genus-DPI.png", 
       plot = plot_weight_final,
       width = 8,
       height = 5,
       units = "in",
       dpi = 600)

This results in a 4800 x 3000 pixel image.

Or let’s say we have a particular pixel dimension we want to get instead. If we want the image to be 2400 x 1500 pixels:

ggsave("figures/weight-by-genus-pixel.png", 
       plot = plot_weight_final,
       width = 2400,
       height = 1500,
       units = "px")

This results in an image with those pixel dimensions, and the default value of 300 DPI has been entered into the image metadata. This means the image will be sized at 8 x 5 inches on a page by default, and if it is resized to be larger than this, it will look bad.
